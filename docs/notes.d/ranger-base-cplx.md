# ranger-base-cplx — a carried mark has to describe the PID it is about

ranger-base-twaq made the availability mark ride `posse relaunch`,
because the fact it states — *this session is not running the pair its
PID names* — survives a refresh. What rode with the fact was the
SENTENCE, and the sentence names the tier and the model the PID asked
for **at the fall**. twaq's condition (`runtime != own || tier !=
ownTier`) rules on the fact and only the fact, so it drops the mark on
exactly one edit: `tier:` moved to what the session is really running.
Edit `tier:` to a THIRD value and the pair still differs, the mark
rides, and `posse list`, the receipt and the meta all say "architect:
tier strong wants claude-fable-5-1" about a PID that asks `fast` —
neither clause true of it — on the one surface an operator reads to
decide whether to act.

The fix re-derives rather than drops (`App.CarriedMark`, modelavail.go).
Carried verbatim while the line still OPENS with what this PID asks
today; otherwise a new line from today's PID and the pair the session
really runs: `architect: tier fast wants claude-sonnet-5 — this session
is running claude-opus-5 from an earlier fall`.

**Why not drop it**, which is the shape the bead offered first: the two
consequential halves are still RIGHT on that board — the ⤵️fallback tag
is earned and `effectiveTier` answers `standard`, which is what the
session runs. Dropping the mark takes both down with the stale
explanation, and the third-tier board is exactly where they are
load-bearing: dispatch would tell a persona on claude-opus-5 that it is
thinking at `fast`. Measured, not argued — the mutant that returns `""`
instead of re-deriving reds four assertions including that one.

**The check is anchored on the separator**, not just the clause:
`preflightWants(persona, tier, model) + " — "`. Without the separator a
model id that is a strict PREFIX of the one the mark names reads as the
same ask, so a `model_strong:` overlay rolling `claude-fable-5-1` back
to `claude-fable-5` would carry a line naming an id nothing asks for.
`preflightWants` is a function and not three literals for the same
reason: the check and the two producers must not drift apart.

Pinning note: four arms, six mutations, each checked to fail — the
pre-fix carry (the third-tier and hop pins red, with the bead's own
measured text), re-derive-always (the byte-identity pin red), drop
instead of re-derive (the third-tier pin's four "halves survive"
assertions red), the tail without `hopDesc` (the hop pin red),
re-deriving from the RUNNING pair instead of the PID's (three pins
red), and the prefix test without the separator (the model-bump pin
red).

NOT this bead, and still open: `RelaunchAgent`, the crash-restart path,
re-types into a live pane and writes the meta back with the mark
untouched. It never had twaq's condition either — neither the drop nor
this re-derivation — so a PID edited under a crashed CLI comes back
wearing whatever the fall wrote. Filed as ranger-base-xa526.
